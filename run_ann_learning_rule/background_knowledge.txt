Background Knowledge for Task: Truncated Forward-RTRL

PURPOSE:
Test whether temporal windowing (propagating the full Jacobian for K steps then resetting)
can solve the copy task. This answers: is temporal depth the key missing ingredient?

ALGORITHM:
Standard RNN: h_t = tanh(W_rec @ h_{t-1} + W_in @ x_t + b)

Truncated forward-RTRL with window K:
- Maintain the full RTRL Jacobian J[i,j,k] = dh_t^i / dW_rec[j,k]
- Every K steps, reset J = 0
- Within the window, propagate exactly as in full RTRL:
  J_new[i,j,k] = phi'(a_t^i) * (sum_l W_rec[i,l] * J[l,j,k] + delta(i==j)*h_{t-1}^k)
- When computing weight updates, use the current (windowed) Jacobian

KEY INSIGHT:
- Full RTRL accumulates influence from ALL past timesteps → 100%
- Rank-1 trace is a one-step approximation → 28%
- Truncated RTRL captures K steps of influence → somewhere in between

FOR THE COPY TASK (seq_len=10):
- Total sequence length: 2*10 + 1 = 21 timesteps
- Input phase: steps 0-9 (symbols presented)
- Blank phase: steps 10-19 (blank input)
- Go signal: step 20
- Output phase: steps 11-20 (must recall symbols)
  Wait — in our implementation the output is at the LAST 10 steps: steps 11-20.
  The delay between symbol input and recall is: step 0 symbol must be recalled at step 11 = 11 steps delay.
  Step 9 symbol must be recalled at step 20 = 11 steps delay.
  So ALL symbols have exactly 11 steps of delay.

- If window K >= 21 (entire sequence), truncated = full RTRL → 100%
- If window K = 11, the Jacobian at output time carries info from 11 steps back,
  which is exactly the delay. Should work if the window aligns correctly.
- BUT: the reset timing matters! If we reset at step 10 and output is at step 11-20,
  then at step 11 we only have 1 step of Jacobian (just reset at 10). Bad!
  If we reset at step 0, 21, etc. (once per sequence), that's K=21 = full RTRL.

IMPLEMENTATION NOTE:
The reset schedule needs to be careful. Two approaches:
1. FIXED PERIODIC RESET: Reset every K steps regardless of task structure.
   The Jacobian at any output step has between 1 and K steps of accumulated info.
2. SLIDING WINDOW: Instead of resetting, maintain the Jacobian but "decay" old info.
   This is like a soft window.

For simplicity, let's use FIXED PERIODIC RESET. The window starts at multiples of K.
At output time t, the Jacobian captures info from step (t - t%K) to step t.
The worst case is when t%K = 0 (just reset), having only 1 step of info.
The best case is when t%K = K-1, having K steps of info.

For K=21 (full sequence): always has full info → 100%
For K=15: output steps 11-20. If reset at step 0 and 15:
  - Steps 11-14: have 11-14 steps of info (from step 0) ← good
  - Steps 15-20: have 0-5 steps of info (just reset at 15) ← bad!
  So periodic reset at K=15 is problematic.

BETTER APPROACH: Don't use periodic reset. Instead, use a SLIDING WINDOW:
Maintain the Jacobian but multiply by a decay factor each step.
J_new = decay * phi' * (W_rec @ J_old + direct)
With decay < 1, old info fades exponentially. Effective window ≈ 1/(1-decay).
- decay = 0.0: rank-1 (no memory in trace)
- decay = 0.9: effective window ≈ 10 steps
- decay = 0.95: effective window ≈ 20 steps
- decay = 1.0: full RTRL (no decay)

THIS IS ACTUALLY JUST FULL RTRL WITH TRACE DECAY — which we already tested partially.
But the key difference from Exp03/04: in those experiments, the trace_decay was applied
to a RANK-1 trace. Here we apply it to the FULL Jacobian.

EXPERIMENTAL PLAN:
Test both approaches:
1. Periodic reset: K = {5, 7, 10, 15, 21} (21 = full sequence = upper bound)
2. Exponential decay on full Jacobian: decay = {0.8, 0.9, 0.95, 0.99, 1.0}

hidden=64, copy task seq_len=10, 10000 iters, batch=32, lr=0.005, random feedback.
Compare accuracy for each setting.

EXPECTED OUTCOMES:
- K=21 or decay=1.0: should match full RTRL (100%)
- K≥11 with good alignment: should be near 100%
- K=5-7: partial credit, maybe 50-80%?
- decay=0.9 (eff window ~10): may work if 10 steps is enough
