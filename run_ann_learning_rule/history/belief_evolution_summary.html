Belief Evolution Analysis

Tracking the evolution of scientific beliefs, self-corrections, and bug-induced artifacts in an autonomous research agent investigating biologically plausible RNN learning rules.

Executive Summary

Over 5 experimental iterations, the research agent investigated what makes BPTT (backpropagation through time) effective for training recurrent neural networks, and what prevents biologically plausible alternatives from matching it. The agent explored and systematically eliminated three candidate bottlenecks: (1) random feedback alignment, (2) optimizer choice (Adam vs SGD), and (3) eligibility trace quality. Only the third proved to be the true bottleneck. Along the way, the agent was misled by a buggy experiment (Exp03) that produced artificially low results, leading to a temporary false belief that optimizers matter. This was corrected in Exp04.

1. Validated Scientific Conclusions

The Definitive Finding (Exp04, Snapshot 6)

Trace quality is the sole determinant of learning rule effectiveness for memory tasks in vanilla RNNs.

  • Full RTRL (exact forward-mode gradient) + random feedback + plain SGD achieves 100% accuracy on copy task (T=10).
  • Rank-1 eligibility traces (as in RFLO) cap at ~28-34% regardless of optimizer (SGD, momentum, Adam) or feedback mechanism (random or exact).
  • Random feedback alignment works perfectly when gradient information is correct.
  • The optimizer (Adam, momentum, SGD) is irrelevant when the trace/gradient is exact.

How Understanding Built Up Incrementally

Step 1 (Literature Review): Identified that no existing method extends to gated architectures (GRU/LSTM). Established RFLO as the simplest baseline to understand.
Step 2 (Exp01): Discovered RFLO performs much worse than BPTT (29.7% vs 73.5%). But BPTT also underperformed due to alpha=0.2 causing information decay.
Step 3 (Exp02): Confirmed two things: (a) BPTT reaches 100% with alpha=1.0 (the architecture is fine), and (b) RFLO caps at 34.5% regardless of hyperparameters (fundamental limitation).
Step 4 (Exp03): Attempted ablation but implementation bugs produced misleading results (C3=40% and C4=13.8%). Led to false hypothesis H8 about optimizer importance.
Step 5 (Exp04): Definitive experiment resolving all ambiguity. Full RTRL + Random FB = 100%. Trace quality is everything.

4. Self-Corrections

4.1 The Optimizer Red Herring (H8: 65% confidence to FALSE)

This is the most dramatic self-correction in the research trajectory. After Exp03, the agent observed that full RTRL + SGD only achieved 40.4% accuracy (C3), while BPTT + Adam achieved 100%. This led to the formulation of H8: "The main advantage of BPTT is not just the exact gradient, but the OPTIMIZER (Adam) that accumulates second-order statistics."

The agent wrote with 65% confidence: "Local learning rules using raw SGD-style updates may be fundamentally limited even with exact gradients. A biologically plausible analog of momentum/Adam may be needed (e.g., synaptic metaplasticity, homeostatic mechanisms)."

This was completely wrong. Exp04 showed that full RTRL + Random FB + plain SGD reaches 100% accuracy. The Exp03 result of 40.4% was an implementation artifact, not a fundamental limitation. The optimizer never mattered at all.

Epistemics lesson: The agent built an entire theoretical narrative (synaptic metaplasticity, homeostatic mechanisms) on top of a single buggy experimental result. The theory was intellectually coherent but empirically unfounded. Had the agent first verified the anomalous result before theorizing, this detour would have been avoided.

4.2 Random Feedback: From Concern to Non-Issue (H4: 55% to FALSE)

From Snapshot 1 through Snapshot 4, the agent maintained moderate confidence (50-55%) that random feedback alignment was a significant bottleneck. This was a reasonable prior based on the literature (feedback alignment is known to degrade in deep networks). However, Exp03 first showed that exact feedback did not help (C2=26.5% vs C1=28.4%), and Exp04 confirmed definitively that random feedback + full RTRL = 100%.

The correction here was gradual and evidence-based. The agent first reduced confidence from 55% to 25% after Exp03, then to FALSE after Exp04. This is an example of proper Bayesian updating.

4.3 The Alpha Parameter Confusion (H6: Quick Resolution)

In Exp01, BPTT only achieved 73.5% on a task it should solve perfectly. The agent initially wondered if BPTT itself was limited on vanilla RNNs, or if something was wrong with the task. The resolution came quickly in Exp02: the leaky integration parameter alpha=0.2 was causing information to decay before the output phase. Setting alpha=1.0 (standard non-leaky RNN) gave 100% accuracy.

This was a clean self-correction: the agent identified the confound, ran a diagnostic experiment, and resolved the issue in one iteration.

4.4 RFLO Performance: From Hopeful to Clearly Insufficient (H1: 55% to FALSE)

The agent initially gave 55% confidence that RFLO-style approaches could train RNNs "within reasonable range of BPTT." This confidence was incrementally reduced as evidence accumulated:

  • Snapshot 2: Raised to 60% (literature review showed the approach is "well-established")
  • Snapshot 3: Dropped to 45% (Exp01 showed large gap)
  • Snapshot 4: Dropped to 30% (Exp02 showed saturation at 34.5% is fundamental)
  • Snapshot 5: Dropped to 20% (Exp03 confirmed across conditions)
  • Snapshot 6: Marked FALSE (definitive evidence from Exp04)

5. Bug-Induced Artifacts

5.1 Experiment 03: Multiple Implementation Issues

Bug Description

Condition C4 (exact feedback + full RTRL): Reported 13.8% accuracy -- worse than random. This condition should theoretically equal or exceed BPTT (100%). The agent correctly flagged this as "anomalous" and suspected a learning rate mismatch or sign error.

Condition C3 (random FB + full RTRL): Reported 40.4% accuracy. Exp04 later showed the same configuration achieves 100%. The agent later noted this was "likely due to an implementation issue" -- possibly a bug in the einsum operation or incorrect batch accumulation of dW_rec.

What False Conclusions Were Drawn

  1. H8 (optimizer hypothesis): The 40.4% C3 result made it appear that full RTRL + SGD was fundamentally limited, leading to the hypothesis that Adam's adaptive learning rates were essential. This was false.
  2. Inflated importance of trace quality relative to actual: Because C3 underperformed (40% instead of 100%), the agent concluded the trace improvement was "modest" (+12% over rank-1). In reality, the improvement is from ~28% to 100% -- a complete solution, not a modest improvement.
  3. Unnecessary research direction: The agent began planning experiments to test "biologically plausible momentum" and "synaptic metaplasticity" as solutions to the perceived optimizer problem. These would have been wasted experiments.

How the Bug Was Detected and Corrected

The agent detected the bug through two mechanisms:

  1. Theoretical inconsistency: C4 (exact FB + full RTRL) should approximate BPTT. Getting 13.8% was flagged immediately as "anomalous" and a candidate for debugging.
  2. Replication in Exp04: When a cleaner implementation was written for Exp04, the full RTRL + random FB condition achieved 100%, directly contradicting Exp03's 40.4%. This proved the Exp03 implementation was buggy.

The agent noted in the final logbook: "Exp03's C3 result (40%) was likely due to an implementation issue (possibly in the einsum or the loop where we accumulate dW_rec across batch incorrectly)."

5.2 Experiment 01: Alpha Parameter Artifact

In Exp01, both BPTT (73.5%) and RFLO (29.7%) underperformed due to alpha=0.2. The leaky integration caused information to decay exponentially, making it impossible for either method to perform well on a memory task. This is not a "bug" per se -- it is a hyperparameter choice that created an artificial ceiling -- but it did lead to temporary confusion about whether BPTT could even solve the task.

6. Lessons Learned: Research Epistemics

6.1 Verify Anomalous Results Before Theorizing

The most costly error was building a theoretical framework (H8: optimizer as bottleneck) on top of a single unreplicated result (Exp03 C3=40.4%). The result was internally inconsistent (C4 was even lower), which should have been a stronger signal to debug rather than theorize. Rule: When a result contradicts theory (C4 should beat C1 but does not), prioritize debugging over explanation.

6.2 The Value of Factorial Experimental Design

Exp04's comprehensive design (crossing trace type x feedback type x optimizer type) was far more informative than Exp03's partial design. By testing all combinations, Exp04 left no room for confounds and produced a clear, unambiguous conclusion. The extra compute cost was repaid by eliminating days of potential confusion.

6.3 Incremental Confidence Updates Work

The agent's handling of H1 (RFLO viability) demonstrates proper epistemics: confidence was reduced incrementally as evidence accumulated (55% to 60% to 45% to 30% to 20% to FALSE). At no point did the agent over-react to a single experiment or under-react to cumulative evidence.

6.4 Implementation Bugs Are Scientific Risks

Exp03's bugs were not caught until Exp04 was run. During the interval (Snapshot 5), the agent made planning decisions (prioritizing optimizer experiments) based on incorrect data. In computational research, implementation errors can look like scientific findings. Safeguards include:

  • Sanity checks (does C4 match BPTT? If not, debug first)
  • Minimal reproducible configurations (test with known-correct smaller cases)
  • Independent reimplementation (Exp04 used a different code path, exposing the bug)

6.5 Correct Conclusions Often Emerge from Incorrect Paths

Despite the Exp03 detour, the agent ultimately reached the correct conclusion (trace quality is everything) and identified the correct next steps (approximate RTRL). The buggy experiment did not permanently mislead the research -- it caused a one-step delay. This is because the agent maintained a culture of verification: each new experiment was designed partly to validate assumptions from the previous one.

6.6 The Importance of Null Results

The definitive finding that "random feedback works perfectly" and "optimizer is irrelevant" are null results with respect to those factors -- they show that two plausible bottlenecks are in fact non-issues. These nulls are as scientifically important as the positive finding (trace quality matters) because they drastically simplify the design space for the novel algorithm.
