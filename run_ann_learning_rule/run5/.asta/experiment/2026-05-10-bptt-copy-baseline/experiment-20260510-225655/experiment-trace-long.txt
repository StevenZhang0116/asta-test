============================ SYSTEM PROMPT ===========================


You are an autonomous research scientist, and have been tasked with creating and carrying out a plan of research.

I'll provide you a top-level Research Task (e.g., "Characterize how well the language model Llama can perform 2-digit addition.").

First, decide on the appropriate strategy for performing the task, either plan (for more complex tasks) or simply do it (for simpler tasks).

Then:
 - For a 'do' strategy, you'll generate the Python code and execute it. This strategy essentially treats the task as a 1-step plan (so no planning step needed).
 - For a 'plan' strategy, you'll:
     1. Generate a plan
     2. Execute the plan, by iteratively working through each step. At each step, you generate Python code to perform the step, then I will execute the code for you and show you the results, then you'll reflect on what do to next.

Here are details on each of those phases:

======================================================================
	PHASE 1. PICK A STRATEGY
======================================================================

You'll be asked to reflect on the immediate task, and decide on the appropriate strategy to follow, one of:
 - do: a task you understand and can do directly in Python, with one or a few commands
 - plan: a larger but well-defined task, that you can generate a plan for (then subsequently follow)

Answer with a JSON structure of the form: {"strategy":STRATEGY, "explanation": EXPLANATION}, where 
 - STRATEGY is either "do" or "plan"
 - EXPLANATION is a natural-language explanation

Some examples:

Task: What is 1 + 1?
{"strategy":"do", "explanation":"A single line of Python will answer this request, so no planning needed."}

Task: How good is Llama at science?
{"strategy":"plan", "explanation":"This involves multiple steps, so planning is needed."}

======================================================================
	PHASE 2. GENERATING A PLAN (for the 'plan' strategy)
======================================================================

 - Each plan step should be expressed in natural language.
 - Each plan step should be implementable in Python (done at a later sage).

When generating a plan, return the plan as a JSON object with the following structure:
     {"plan": [{"step_number":1, "step":DESCRIPTION}, {"step_number":2, "step":DESCRIPTION}, ....]}

======================================================================
	PHASE 3. EXECUTING A PLAN (for the 'plan' strategy)
======================================================================

1. Overview

Given a plan, we will then interact to repeatedly execute an ACTION then REFLECTION cycle to perform each step in the plan in turn.

In the ACTION step, you'll generate some Python code to perform the next step in the plan. I'll then execute the Python code and show you the results.

In the REFLECTION step, you'll reflect on whether the code execution was successful, and what to do next. Your possible next steps can include redoing the entire plan itself, or stopping if the research task is complete.

2. The Action step

I will give you the next step to perform, and you'll return an implementation of that step in Python, along with a "thought" describing your reasoning. In this step, you should return a JSTON object of the form:

      {"thought":THOUGHT, "action":PYTHON_CODE}

I'll then execute the code and add the results at the end of the conversation, then ask you to reflect on the results.
Several examples are given below.

BACKGROUND KNOWLEDGE FOR STEP 3: BPTT baseline on copy task

TASK
----
Run a BPTT baseline experiment on a short supervised copy task using a vanilla RNN,
so that downstream steps (implementing RFLO, e-prop, and STC-Credit from design_step2.md)
have a reference performance target.

PURPOSE
-------
`design_step2.md` specified STC-Credit, the candidate biologically-plausible rule for H1.
Before implementing it, we need a well-characterized BPTT baseline on the same architecture
and task. Success criterion (from mission.md): "Performance on short-sequence supervised
tasks is within reasonable range of BPTT" — so we must first quantify BPTT's performance.

TASK SPEC — COPY TASK (length 10)
----------------------------------
Input: At t = 1..5, 5 symbols drawn uniformly from an alphabet of 8 (one-hot encoded,
so input dim = 8 + 2 = 10; the extra 2 channels are "blank" and "delimiter").
From t = 6..10 the input is "blank".
At t = 10 a "go" signal appears (delimiter channel).
Target: output the original 5 symbols at t = 11..15 (output dim = 8).

This is the canonical short copy task used for RFLO / e-prop comparisons and is simple
enough that a small RNN trained with BPTT should learn it cleanly, giving us a non-degenerate
reference. Total sequence length = 15 timesteps.

EXPERIMENT CONFIGURATION
------------------------
- Architecture: vanilla (Elman) RNN
  - Hidden size: 128 (slightly larger than the 64 in design_step2 §7 defaults —
    128 gives cleaner convergence for BPTT baselines and makes the BPTT error floor
    easy to establish).
  - Activation: tanh
  - Input dim: 10 (8 symbols + blank + go)
  - Output dim: 8 (over symbols only)
  - Readout at every timestep; cross-entropy loss only applied on output timesteps t=11..15.
- Optimizer: Adam, lr = 1e-3
- Batch size: 64
- Number of training steps: 3000 (should easily saturate on this task)
- Evaluation: every 100 steps, on 1000 held-out sequences
- Metrics:
  - Per-symbol accuracy on the output timesteps
  - Sequence-level accuracy (all 5 symbols correct)
  - Cross-entropy loss
  - Wall-clock time per 100 training steps

DEVICE HANDLING
---------------
- Detect GPU at runtime via torch.cuda.is_available()
- Move model + batches to GPU if present, otherwise CPU
- Log the device at start
- Code must work on both

OUTPUTS
-------
The run-experiment skill (Panda) will produce standardized artifacts in
.asta/experiment/... :
  - experiment.py (final experiment code)
  - experiment-trace.txt (run log)
  - experiment.html (rendered report)
  - experiment-artifacts.py (any intermediate artifacts)

The research-loop needs to extract:
  - Final per-symbol and sequence-level accuracy
  - Learning curve (loss vs step)
  - Wall-clock and device used

INSTRUCTIONS FOR run-experiment (PANDA)
---------------------------------------
The specific research question for Panda:

  "Train a vanilla Elman RNN with backpropagation-through-time (BPTT) on a standard
   copy task where a 5-symbol sequence from an alphabet of size 8 is presented during
   timesteps 1..5, followed by 5 blank timesteps and a single 'go' cue at timestep 10,
   and the network must reproduce the 5 symbols at timesteps 11..15. Report the per-symbol
   classification accuracy, sequence-level accuracy, and cross-entropy loss learning curve.
   Use Adam with lr=1e-3, batch size 64, hidden size 128, tanh activation. Run for 3000
   training steps with evaluation every 100 steps on 1000 held-out sequences. Use GPU if
   available (torch.cuda.is_available()); fall back to CPU. Log the device. Do not use
   any built-in PyTorch RNN module — implement the recurrent dynamics explicitly as
   h_t = tanh(W h_{t-1} + U x_t + b) with readout ŷ_t = V h_t, so that this baseline
   has identical structure to the RNN we will later train with non-BPTT rules."

The experiment should establish:
  (a) that BPTT on this architecture/task reaches near-perfect per-symbol accuracy
      (>95%) and near-perfect sequence-level accuracy, within 3000 steps;
  (b) an approximate learning-curve landmark: at what step does test accuracy
      first exceed 90%? This is the number future local-rule experiments will
      try to match (or exceed).

# --- Data generator ---------------------------------------------------------
def generate_batch(batch_size, device):
    """
    Generate a batch of copy-task sequences.
    
    Input shape:  (batch, T=15, input_dim=10)
    Target shape: (batch, 5) -- integer class labels for output timesteps
    
    Timeline (0-indexed):
      t=0..4  : one-hot symbol in channels 0..7
      t=5..8  : blank (channel 8 = 1)

      t=10..14: blank input; network must output the 5 symbols
    """

    x[:, 9, GO_CH]   = 1.0

    x[:, 10:15, BLANK_CH] = 1.0

    targets = symbols  # shape (batch, 5)

# --- Vanilla Elman RNN -------------------------------------------------------
class ElmanRNN(nn.Module):
    """
    Explicit Elman RNN:
      h_t = tanh(W @ h_{t-1} + U @ x_t + b_h)
      y_t = V @ h_t + b_y
    No built-in PyTorch RNN modules used.
    """
    def __init__(self, input_dim, hidden_dim, output_dim):
        super().__init__()
        self.hidden_dim = hidden_dim
        
        # Recurrent weight matrix W: (hidden, hidden)
        self.W = nn.Parameter(torch.randn(hidden_dim, hidden_dim) * 0.1)
        # Input weight matrix U: (hidden, input)
        self.U = nn.Parameter(torch.randn(hidden_dim, input_dim) * 0.1)
        # Hidden bias
        self.b_h = nn.Parameter(torch.zeros(hidden_dim))
        # Readout weight matrix V: (output, hidden)
        self.V = nn.Parameter(torch.randn(output_dim, hidden_dim) * 0.1)
        # Readout bias
        self.b_y = nn.Parameter(torch.zeros(output_dim))
    
    def forward(self, x):
        """
        x: (batch, T, input_dim)
        Returns logits at output timesteps: (batch, N_SYMBOLS, output_dim)
        """
        batch_size, T, _ = x.shape
        h = torch.zeros(batch_size, self.hidden_dim, device=x.device)
        
        output_logits = []
        
        for t in range(T):
            x_t = x[:, t, :]  # (batch, input_dim)
            # h_t = tanh(W h_{t-1} + U x_t + b_h)
            h = torch.tanh(
                h @ self.W.T + x_t @ self.U.T + self.b_h
            )
            # Collect logits only at output timesteps
            if t >= OUT_START:
                y_t = h @ self.V.T + self.b_y  # (batch, output_dim)
                output_logits.append(y_t)
        
        # Stack: (batch, N_SYMBOLS, output_dim)
        return torch.stack(output_logits, dim=1)
