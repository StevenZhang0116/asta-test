Abstract
--------
Before implementing biologically-plausible learning rules (RFLO, e-prop, and STC-Credit) on recurrent neural networks, it is essential to establish a clear performance reference. This report characterizes the performance of backpropagation-through-time (BPTT) on a standard short-sequence copy task, providing the target metrics that downstream experiments will be evaluated against.

We trained a vanilla Elman RNN with explicit recurrent dynamics (h_t = tanh(W h_{t-1} + U x_t + b_h), y_t = V h_t) on a copy task in which 5 symbols drawn from an alphabet of size 8 must be reproduced after a delay. The network uses 128 hidden units, Adam optimization (lr=0.001), batch size 64, and was trained for 3000 steps with evaluation every 100 steps on 1000 held-out sequences. All experiments ran on an NVIDIA A100-PCIE-40GB GPU.

BPTT achieved perfect performance on this task: 100% per-symbol accuracy and 100% sequence-level accuracy, first reached at step 200 and maintained through step 3000. Notably, per-symbol accuracy already exceeded 90% at the first evaluation checkpoint (step 100, 99.72%). The final cross-entropy loss was 0.0002, representing a 10,822-fold reduction from initialization. Training was computationally inexpensive, completing in approximately 25 seconds.

These results establish an upper-bound reference for the copy task under this architecture: BPTT solves it essentially perfectly and very rapidly. Future experiments with local learning rules should be interpreted against this ceiling. We caution that this task is deliberately simple, and strong BPTT performance here does not imply that bio-plausible rules will face similarly easy conditions -- the gap between BPTT and local rules may be substantial on harder tasks.


1. Introduction
---------------
Understanding how the brain learns from experience is one of the central challenges in neuroscience. Backpropagation, the dominant algorithm for training artificial neural networks, is widely regarded as biologically implausible because it requires non-local information, symmetric weight transport, and precise error signals that are difficult to reconcile with known neural circuitry. This has motivated a growing body of research into local learning rules -- algorithms such as RFLO, e-prop, and spike-timing-dependent credit assignment (STC-Credit) -- that approximate the performance of backpropagation while respecting biological constraints.

A necessary precondition for evaluating any such biologically-plausible learning rule is a well-characterized baseline: we must know what a standard backpropagation algorithm achieves on the same architecture and task before we can assess whether a local rule comes "within reasonable range." Without this reference, it is impossible to determine whether a local rule's performance represents success or failure.

This report addresses that precondition. We implement and evaluate backpropagation-through-time (BPTT) on a standard short-sequence copy task using a vanilla Elman RNN with explicitly coded recurrent dynamics -- the same architecture that will subsequently be trained with RFLO, e-prop, and STC-Credit. The copy task requires a network to memorize 5 symbols presented sequentially, maintain them across a blank delay period, and reproduce them in order after a "go" cue. It is a canonical benchmark for evaluating sequence memory in recurrent networks, chosen for its clarity and the fact that it is well within the capacity of a small RNN trained with BPTT.

The main findings are straightforward: BPTT solves this task essentially perfectly, reaching 100% per-symbol accuracy and 100% sequence-level accuracy by step 200 out of 3000 training steps. The 90% per-symbol accuracy threshold was crossed at the very first evaluation checkpoint (step 100). These results establish a clear and demanding upper bound: future local-rule experiments on this task should aim for greater than 95% per-symbol accuracy to be considered competitive with BPTT. We emphasize that the simplicity of the copy task means these results reflect a best-case scenario for BPTT, and the gap between BPTT and local rules may widen considerably on longer sequences or more complex tasks.

2. Approach
------------
TASK DESIGN

We used a standard short-sequence copy task with total sequence length T=15 timesteps. The input dimensionality is 10, comprising 8 symbol channels, 1 blank channel, and 1 go/delimiter channel. The task proceeds as follows:

  Timesteps t=1..5   : One of 8 symbols is presented at each step, drawn
                       uniformly at random and encoded as a one-hot vector
                       in channels 0-7.
  Timesteps t=6..9   : Blank input only (channel 8 = 1, all others = 0).
  Timestep  t=10     : Go signal (channel 9 = 1) together with blank
                       (channel 8 = 1). This cues the network to begin
                       reproduction.
  Timesteps t=11..15 : Blank input; the network must output the original
                       5 symbols in order.

The target output at each of the 5 output timesteps (t=11..15) is the integer class label of the corresponding input symbol. Cross-entropy loss is computed only over these 5 output timesteps; no loss is applied during the input or delay phases. The task requires the network to encode 5 symbols into its hidden state, maintain them across at least 5 blank timesteps, and decode them in correct sequential order upon receiving the go cue.

ARCHITECTURE

We implemented a vanilla Elman (simple) recurrent neural network using explicit recurrent dynamics, without using any built-in PyTorch RNN module. The recurrent update and readout equations are:

  h_t = tanh(W @ h_{t-1} + U @ x_t + b_h)
  y_t = V @ h_t + b_y

where:
  x_t   is the input vector at time t (dimension 10)
  h_t   is the hidden state vector (dimension 128)
  y_t   is the pre-softmax output logit vector (dimension 8)
  W     is the 128x128 recurrent weight matrix
  U     is the 128x10 input weight matrix
  b_h   is the 128-dimensional hidden bias vector
  V     is the 8x128 readout weight matrix
  b_y   is the 8-dimensional output bias vector

All weight matrices were initialized from a zero-mean Gaussian with standard deviation 0.1. All bias vectors were initialized to zero. The hidden state h_0 was set to the zero vector at the start of each sequence. The readout y_t is computed at every timestep, but only the outputs at t=11..15 contribute to the loss. This explicit implementation was chosen deliberately so that the architecture is identical in structure to what will later be trained with non-BPTT local learning rules, where the recurrent dynamics must be accessible at each timestep.

The total parameter count is:
  W  : 128 x 128 = 16,384
  U  : 128 x  10 =  1,280
  b_h:        128 =    128
  V  :   8 x 128 =  1,024
  b_y:          8 =      8
  Total         =  18,824 parameters

TRAINING PROCEDURE

Training used backpropagation-through-time (BPTT), in which gradients are propagated through all 15 timesteps of the unrolled computation graph. The optimizer was Adam with learning rate 0.001 and default PyTorch settings (beta1=0.9, beta2=0.999, epsilon=1e-8). The batch size was 64 sequences per update step. Training ran for 3000 gradient update steps. A new random batch was generated at each step, so the network was never trained on repeated sequences.

The loss function was cross-entropy applied to the 5 output timesteps. Concretely, the logits at t=11..15 were collected into a tensor of shape (batch x 5 x 8), reshaped to (batch*5 x 8), and compared against the corresponding integer target labels using PyTorch's CrossEntropyLoss.

EVALUATION PROCEDURE

Every 100 training steps, the model was evaluated on a freshly generated batch of 1000 held-out sequences (also never seen during training). Three metrics were recorded:

  Per-symbol accuracy  : The fraction of individual symbol predictions
                         (across all 5 output positions and all 1000
                         sequences, i.e., 5000 predictions total) that
                         match the target symbol exactly.

  Sequence accuracy    : The fraction of complete sequences (out of 1000)
                         for which all 5 output symbols are predicted
                         correctly.

  Cross-entropy loss   : The average cross-entropy loss over the 5 output
                         positions, computed on the 1000 held-out sequences.

Wall-clock time per 100 training steps was also recorded to characterize computational cost.

HARDWARE AND SOFTWARE

All experiments were run on an NVIDIA A100-PCIE-40GB GPU using CUDA 12.1. The software stack was PyTorch 2.5.1+cu121, NumPy, and Python 3.12 in the panda conda environment. GPU availability was detected automatically at runtime via torch.cuda.is_available(), with CPU fallback implemented for portability.

4. Analysis
----------
RAPID AND COMPLETE CONVERGENCE

The most striking feature of the results is how quickly and completely BPTT solves the copy task. From a random initialization, the network transitions to near-perfect performance within a single evaluation window of 100 steps. To put this in concrete terms: at step 0, the network predicts symbols essentially at chance (11.18% per-symbol accuracy, compared to the 12.5% expected for uniform random guessing over 8 classes). By step 100 -- after seeing only 6,400 training sequences (100 steps x 64 batch size) -- the network achieves 99.72% per-symbol accuracy and 98.60% sequence-level accuracy. This means that out of every 1000 test sequences, 986 are reproduced perfectly in their entirety, and across all 5000 individual symbol predictions, only 28 are wrong.

By step 200, both metrics reach 100% and remain there for the remaining 2800 training steps. This is not a gradual approach to ceiling -- it is a sharp, decisive transition that occurs within the first 7% of the total training budget.

THE COPY TASK AS A MEMORY PROBE

The copy task is specifically designed to probe working memory in recurrent networks. To illustrate what the network must learn, consider an example sequence with symbols [3, 7, 1, 5, 2]:

  t=1:  Input = one-hot(3), channels 0-7.  Network encodes symbol 3.
  t=2:  Input = one-hot(7), channels 0-7.  Network encodes symbol 7.
  t=3:  Input = one-hot(1), channels 0-7.  Network encodes symbol 1.
  t=4:  Input = one-hot(5), channels 0-7.  Network encodes symbol 5.
  t=5:  Input = one-hot(2), channels 0-7.  Network encodes symbol 2.
  t=6:  Input = blank (channel 8).         Network must maintain state.
  t=7:  Input = blank (channel 8).         Network must maintain state.
  t=8:  Input = blank (channel 8).         Network must maintain state.
  t=9:  Input = blank (channel 8).         Network must maintain state.
  t=10: Input = go + blank (channels 8,9). Network begins reproduction.
  t=11: Input = blank. Target = symbol 3.  Network outputs class 3.
  t=12: Input = blank. Target = symbol 7.  Network outputs class 7.
  t=13: Input = blank. Target = symbol 1.  Network outputs class 1.
  t=14: Input = blank. Target = symbol 5.  Network outputs class 5.
  t=15: Input = blank. Target = symbol 2.  Network outputs class 2.

The network receives no input about the target symbols during the output phase -- it must rely entirely on its 128-dimensional hidden state to carry all 5 symbols (each from an 8-class alphabet) across up to 10 blank timesteps. That a 128-unit tanh RNN trained with BPTT can learn to do this perfectly is expected given the architecture's capacity, but it confirms that the task is well-matched to the model and that the training signal is effective.

THE ARCHITECTURE'S EXPLICIT DYNAMICS

A key design choice in this experiment was implementing the recurrent dynamics explicitly rather than using PyTorch's built-in nn.RNN module. The equations used were:

  h_t = tanh(W @ h_{t-1} + U @ x_t + b_h)
  y_t = V @ h_t + b_y

with W (128x128), U (128x10), b_h (128), V (8x128), and b_y (8) as the learnable parameters (18,824 total). This is not merely a software engineering choice -- it is a necessary precondition for fair comparison with local learning rules. RFLO, e-prop, and STC-Credit all require access to the hidden state and pre-activation values at each timestep. By implementing the dynamics step-by-step in a Python loop, we ensure that the baseline and the future local-rule implementations share an identical computational graph structure, differing only in how weight updates are computed.

LOSS TRAJECTORY AND CONFIDENCE

While accuracy saturated at 100% by step 200, the cross-entropy loss continued to decrease smoothly throughout all 3000 steps:

  Step    0:  loss = 2.1644  (near theoretical random baseline of ln(8) = 2.079)
  Step  100:  loss = 0.1776  (91.8% reduction; accuracy already 99.72%)
  Step  200:  loss = 0.0417  (98.1% reduction; accuracy 100%)
  Step 1000:  loss = 0.0016  (99.9% reduction; accuracy 100%)
  Step 3000:  loss = 0.0002  (99.99% reduction; 10,822x total reduction)

This dissociation between discrete accuracy and continuous loss is expected: once the network classifies all symbols correctly, further training sharpens the output distribution (increasing confidence) without changing discrete predictions. The final loss of 0.0002 corresponds to the network assigning very high probability mass to the correct class at every output timestep. This is the characteristic behavior of a well-trained classifier that has saturated its discrete performance metric.

COMPUTATIONAL EFFICIENCY

The experiment completed in approximately 24.6 seconds on an NVIDIA A100-PCIE-40GB GPU (averaging 0.82 seconds per 100 training steps). This is extremely fast for a sequence learning experiment and reflects both the simplicity of the task and the efficiency of GPU-accelerated matrix operations even in an explicit Python loop implementation. The practical implication is that this baseline can be reproduced or extended (e.g., with multiple random seeds) at negligible computational cost.

IMPLICATIONS FOR DOWNSTREAM EXPERIMENTS

These results establish the following concrete reference targets for RFLO, e-prop, and STC-Credit experiments on the same task:

  1. Performance target: >95% per-symbol accuracy and >95% sequence-level
     accuracy. BPTT achieves 100% on both; the 95% threshold provides a
     reasonable margin that accounts for stochasticity in local rules.

  2. Speed target: The 90% per-symbol accuracy landmark occurs at step 100
     for BPTT. Future experiments should report the step at which they
     first cross this threshold for direct comparison.

  3. Capacity confirmation: The 128-hidden-unit Elman RNN has sufficient
     capacity to solve the task perfectly. Any failure by a local rule
     to reach high accuracy is therefore attributable to the learning
     rule itself, not to architectural bottlenecks.

  4. Important caveat: This copy task (T=15, 5 symbols, alphabet-8) is
     deliberately simple. BPTT's near-instant convergence means the
     performance gap between BPTT and local rules may be small here but
     could be substantially larger on longer sequences, larger alphabets,
     or tasks requiring more complex temporal credit assignment. Results
     on this benchmark should not be generalized beyond the specific
     configuration tested.

5. Conclusion
-------------
This experiment successfully establishes a BPTT baseline for the short-sequence copy task, fulfilling its intended purpose as a reference for evaluating biologically-plausible learning rules. The main findings are as follows.

BPTT solves the copy task essentially perfectly. A vanilla Elman RNN with 128 hidden units, trained with Adam (lr=0.001, batch size 64), reaches 100% per-symbol accuracy and 100% sequence-level accuracy on 1000 held-out sequences by step 200, and maintains this performance through step 3000. The 90% per-symbol accuracy threshold is crossed at step 100, the very first evaluation checkpoint. These results confirm that the task is well within the capacity of this architecture and that BPTT provides a clean, unambiguous upper bound for performance on this benchmark.

The practical reference targets for downstream experiments are:
  - Minimum acceptable performance : >95% per-symbol accuracy
  - Minimum acceptable performance : >95% sequence-level accuracy
  - Speed landmark to compare against: step 100 (where BPTT first exceeds 90%)

Several important limitations and caveats must be stated clearly.

First, the copy task used here is deliberately simple. Five symbols, an alphabet of size 8, and a total sequence length of 15 timesteps represent a low-difficulty working memory problem. The fact that BPTT converges in under 200 steps does not mean that local learning rules will face similarly easy conditions -- the computational challenge for local rules arises from the absence of error backpropagation, not from task difficulty per se, and this difference may manifest more severely on harder tasks.

Second, we report results from a single training run with a single random seed. While the results are internally consistent and the task is simple enough that outcome variability is expected to be low, we cannot rule out seed-dependent variation in convergence speed. The 90% landmark at step 100 should be treated as an approximate reference point rather than a precise threshold.

Third, perfect accuracy on a held-out set of 1000 sequences does not guarantee perfect generalization in a strict mathematical sense -- it is a strong empirical indication for this task size, but the evaluation set covers only a small fraction of the possible 8^5 = 32,768 distinct input sequences.

Fourth, this baseline characterizes BPTT on a CPU-friendly, small-scale architecture. Conclusions about the relative efficiency of BPTT versus local rules in terms of wall-clock time should not be drawn from this experiment alone, as the comparison would depend heavily on implementation details of the local rules.

In summary, BPTT on this architecture and task sets a high and clear performance ceiling. The central question for subsequent experiments -- whether RFLO, e-prop, or STC-Credit can come within reasonable range of this ceiling on the same task -- is now well-posed and can be answered with direct comparison against the metrics reported here.
